# v0.1.0 基础设施配置

## 原有问题与本阶段范围

重构开始时，新目录只有 API 启动骨架和 MySQL/SQLite 异步连接管理。对象存储、Redis、Celery、Elasticsearch 和 Milvus 尚未纳入新应用的配置与资源边界。

本阶段在保留 `src/knowledge/` 的前提下，于 `src/knowledge-refactor/` 建立基础设施配置和必要的应用装配。实现优先参考开源 Bisheng 对应组件，并按 knowledge-backend 当前边界裁剪。

## 实际修改与实现结果

- `config.py` 集中定义 MySQL/SQLite、MinIO、Redis、Celery、Elasticsearch 和 Milvus 的运行配置。连接 URL、凭据和可能包含凭据的连接参数不显示在配置对象的 repr 中。
- MySQL/SQLite 由 `DatabaseConnectionManager` 管理异步 engine 和 SQLModel session；成功提交由调用方显式执行，操作异常或取消时回滚。
- MinIO 由 `MinioObjectStorage` 管理。长期对象与临时处理中间对象分别写入长期 bucket 和临时 bucket；缺失 bucket 会在应用启动时创建，临时 bucket 仅在没有既有生命周期规则时设置 3 天过期。未配置匿名访问策略。下载链接由服务授权后签发短时预签名 URL，并允许配置外部可访问 endpoint。
- Redis 由 `RedisConnectionManager` 持有同步和异步客户端，连接按需建立并在应用关闭时释放。Redis URL 可选。
- Celery 在 `app/celery.py` 提供应用工厂，采用 Bisheng 的 JSON 序列化和上海时区配置。Broker URL、task routes 可配置；本阶段未加入业务任务、路由或定时任务，也未配置结果后端。
- Elasticsearch 配置 endpoint 和客户端选项，由 `ElasticsearchConnectionManager` 按需创建同步/异步客户端，并在应用关闭时释放。未配置 endpoint 时不会创建客户端。
- Milvus 配置 `connection_args`，支持 JSON 对象，并沿用 Bisheng 的 `host`/`port` 到 `uri` 转换。Milvus 仍由后续按 collection 和 embedding 创建的向量库实例使用，不在应用启动时连接或创建 collection。
- FastAPI lifespan 负责组装并关闭数据库、MinIO、Redis 和 Elasticsearch 资源；MinIO 初始化失败或应用退出时仍执行资源清理。

## 方法与设计取舍

应用层管理进程级资源生命周期，infrastructure 层封装具体客户端，配置与业务领域模型分开。连接按需创建，避免启动时对 ES、Redis、Milvus 等尚未使用的组件进行无必要的连通性检查。

MinIO 长期文件与可丢弃中间产物分开保存，生命周期只应用于临时 bucket。下载 URL 通过预签名方式产生，权限检查留给调用它的业务服务。既有临时 bucket 生命周期规则会被保留，应用不覆盖运维配置。

Milvus 沿用 Bisheng 的 LangChain 向量库按知识库 collection 初始化方式，因此当前只集中管理连接参数，不额外创建全局 Milvus 管理器。Celery 本阶段提供配置工厂，具体任务发现、worker 入口和任务路由随任务实现接入。

## 验证情况

运行 `PYTHONPATH=src .venv/bin/pytest -q tests/refactor/test_bootstrap.py`：15 项通过。测试覆盖配置环境变量解析、MySQL URL 驱动转换、数据库事务回滚、MinIO bucket 和生命周期处理、对象读写 bucket 选择、预签名 URL、Redis 客户端关闭、Celery 配置、ES 客户端懒加载与关闭，以及应用 lifespan 清理。

运行 `.venv/bin/ruff check src/knowledge-refactor tests/refactor` 和 `.venv/bin/ruff format --check src/knowledge-refactor tests/refactor`：均通过。测试未连接真实 MySQL、MinIO、Redis、Elasticsearch 或 Milvus，因此不代表部署环境连通性已验证。测试输出包含 9 条既有 SQLModel `session.execute()` 弃用警告。

## 影响与后续事项

API 启动配置现在要求提供 MinIO access key 和 secret key；MinIO 服务不可用或 bucket 初始化失败会导致 API 启动失败。Redis 与 Elasticsearch 配置可选。Celery app 工厂要求调用时提供 broker URL。

后续随相应阶段接入 Alembic 迁移、Celery worker/task discovery 与业务路由、健康检查和日志配置。当前没有自动建表、启动时迁移、Celery 业务任务或 Milvus collection 初始化。
